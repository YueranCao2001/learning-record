# 单活动原文抽取：标注规则 v1

本规则在2026-10-24审计运行前写入，用于解释标签，不会添加到模型 prompt。沿用既有 instruction 和 `event`、`time`、`location` 三字段；不能看到输出后修改标签以增加匹配。

## 纳入范围与字段边界

仅纳入一个活动、没有取消或改期冲突、每个目标可用单个连续原文片段表示的通知。出现多个活动、互相冲突的安排、时间拆散成不连续片段或没有唯一合理标签时，先标为待审，不强行选答案。本次审计不覆盖这些情况。

- `event`：活动名称本身；不含“欢迎参加”“诚邀您参加”等邀请语、标题外围引号、冒号或句尾标点。名称包含的“课”“交流会”等保留。不把句首时间或地点当名称。
- `time`：完整且连续的举办时间表达，保留日期/星期、上午/下午等限定词和时刻；连续的起止区间整体保留。不换算相对日期、不补全年份、不自行规范化标点。
- `location`：明确的举办场地原文，包括楼层、房间等限定。通知明确给出的线上场地也可提取；不包含“地点为”等引导词。
- 未提供、待定、另行通知等情况对应 JSON `null`，不是字符串 `"null"` 或 `"待定"`。

## 输出和审查

JSON 对象恰好三个键；值为非空字符串或 `null`。解析后比较键值，不因空格、换行和键顺序扣分。不接受 Markdown 围栏、额外说明或额外键。所有非空目标必须是连续原文片段；片段检验不能证明语义标注正确。

ID、来源组、文本不得与既有15条记录重复；本次组 ID 代表来源通知，不代表模板族。同一助手编写标签、题目和审查程序，不构成独立人工标注或封存测试。真实人工复核状态保持 `pending`。

本轮结果揭晓后，该审计集视为开放诊断集；未来若用于改数据或调参，不能再把它报告为独立测试。
