# 本地推理服务阶段报告

2026 年 11 月 23 日完成本地推理服务第一阶段。验收入口可以从新实例复现正常流式回复、客户端超时、排队断开和入槽后取消。此前对并发、前缀缓存及槽释放时点的压测已归档。

## 第一阶段回归验收

运行 [一键回归命令](README.md#一键回归验收) 后，脚本启动独立回环服务并输出 JSON。两次新实例运行各通过 5 项，均以退出码 `0` 结束。[首次报告](results/stage-acceptance/trial-01.json) · [再次报告](results/stage-acceptance/trial-02.json)

| 路径 | 通过条件 |
| --- | --- |
| 正常流式回复 | HTTP 200，多段正文拼接后与固定答案相同，正常停止 |
| 放行前超时 | 占槽请求仍在运行，预算过期的候选未开始 HTTP，占槽请求正常结束 |
| 排队断开 | 断开的候选在观察窗口内没有进入槽，后续请求正常完成 |
| 入槽后断开 | 目标任务号匹配取消和释放事件，后续请求复用同一槽并完整结束 |
| 保留排队连接 | 候选在槽空出后进入推理并正常结束，后续请求正常完成 |

临时端口占用的故障演练写入 `startup` 失败项，并以退出码 `1` 结束。验收以流程和结果为通过条件，耗时和日志保留在报告中，供复跑比较。

## 环境与验收

- Windows 11，RTX 5070，驱动 `610.88`。Ollama `0.40.17`，`qwen3:8b`，模型 ID `500a1f067a9f`。三轮复验记录了相同的完整模型摘要和 `Q4_K_M` 量化，模型显存计数均为 `5584495574` 字节。[三轮运行清单](results/concurrency-recheck/manifest.json)
- 服务绑定 `127.0.0.1`，两个条件共用同一服务实例和两个推理槽，每槽上下文 2048，温度为 0，关闭思考输出。
- 每次独立启动先用 4 条请求预热，然后执行 4 组配对。每个条件每组发送 2 条短提示和 2 条长提示，输入分别为 51 和 750 token。不同请求使用不同的数字开头，正式请求实际只复用 3–5 个前缀 token。
- 每条回复须通过 HTTP 200、目标文本和 `done_reason: stop` 检查。正式请求每条生成 20 token，各轮实际峰值在途数与设定一致。吞吐用整轮输出 token 总数除以墙钟时间，延迟从每条请求发出开始计时。预热记录保留在原始文件中。

## 阶段结论

普通 HTTP 和流式读取均已验收。单并发基线表明长提示的前缀大量命中时，客户端更快收到首段正文。低缓存的短长混合负载下，并发 2 在四次运行中持续提高整轮吞吐，同时增加单条延迟。延迟优先的调用可用并发 1 作为当前对照，批量吞吐优先的调用可用并发 2 作为当前对照。

复验只覆盖同一台机器、两个服务端槽和固定的短输出。随后完成 64 条等长输入对照，比较 20 与 117 token 输出下的并发收益。[长输出逐次结果](results/2026-11-23-output-length.json)

之后固定两个槽，用 117 token 输出跑完 96 条请求。并发 2 和 4 的吞吐中位数分别为 162.19 和 163.58 token/s，首段正文 P90 分别为 282.15 和 1706.02 ms。[并发 2 与 4 逐次结果](results/2026-11-23-queue.json)

在新增的 64 条批量提交请求中，客户端最多放行 2 条时，HTTP 阶段至首段正文的 P90 从 1707.50 ms 降至 287.90 ms。按批次提交时刻计时，首段与完整回复的 P90 则分别只相差约 12 和 8 ms。[客户端放行逐次结果](results/2026-11-23-admission.json)

48 条首段正文超时实验使用从整批提交起算的预算，分别观察到等待放行和 HTTP 调用期间的超时。紧接着提交的 4 个宽预算批次共 16 条全部完成。[首段超时逐次结果](results/2026-11-23-deadline.json)

单槽服务的 6 对取消对照里，主动断开到观察到槽释放的中位数为 15.21 ms。后续请求重新拿到同一个槽，12 次均通过。这个时间按客户端收到 runner 日志计量。[槽释放逐次时间线](results/2026-11-23-cancellation.json)

双槽的 6 对实验中，断开一条流仅取消目标任务，保留的 12 条流和第三条请求的 12 次回复均完整通过。断开组后续请求每次复用目标槽，首段正文中位数为 75.96 ms。[双槽逐次时间线](results/2026-11-23-dual-cancellation.json)

首段正文前的取消对照共 18 次。排队时断开的 6 条候选均未进入槽，保留连接的 6 条排队候选均进入并正常完成。已占槽的 6 条断开后，收到槽释放日志的中位数为 317.60 ms。[首段前取消逐次时间线](results/2026-11-23-pre-first-cancel.json)

随后固定入槽后立即断开，比较 280、538、882、1570 token 四档提示。32 次后续回复全部通过，断开到槽释放日志的中位数依次为 70.26、121.69、179.19、316.47 ms。同一请求从取消日志到释放日志约为 11 ms。[提示长度逐次结果](results/2026-11-23-cancel-length.json)

同一 1570-token 提示的 8 对缓存实验中，新开头复用 3–5 token，预热后原样重发复用 1569 token。断开到槽释放日志的中位数从 326.58 降到 19.65 ms，16 条后续回复均通过。[缓存对照逐次结果](results/2026-11-23-cancel-cache.json)

固定 1570-token 输入，加入三档部分命中后，未复用 1250、906、562 token 时，槽释放日志的中位数为 264.08、204.29、133.50 ms。包括两端对照共 25 条后续回复均通过。[部分缓存逐次结果](results/2026-11-23-cancel-partial-cache.json)

总长度 882 和 1570 token 的配对试验中，固定相同未缓存后缀。未复用 347 和 691 token 时，长提示相对短提示的释放日志中位配对差分别为 1.72 和 5.73 ms，32 条后续回复均通过。[等量未缓存逐次结果](results/2026-11-23-cancel-matched-suffix.json)

顺序重启两个新实例并重复相同输入后，三个实例的中位配对差在 347-token 后缀下为 1.72–1.99 ms，在 691-token 后缀下为 5.59–6.22 ms。48 对均为长提示的槽释放日志更晚，96 条后续回复全部通过。[复验 1](results/matched-suffix-recheck/trial-01.json) · [复验 2](results/matched-suffix-recheck/trial-02.json)
