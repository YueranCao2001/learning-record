# 2026-11-24：本地推理实作：缩小可持续到达速率范围

## 今日目标

继续本地推理服务第二阶段。昨天每秒 1 条时排队很短，每秒 2 条时已有明显积压。今天固定模型、输入输出和并发配置，延长测试窗口，比较每秒 1.25 和 1.5 条时前后半程的排队变化。完成条件是两档各跑两轮，核对实际提交速率、前后半程排队、末次提交后未完成量及输出验收。[昨日对照](2026-11-23-local-inference-http-smoke.md)

## 核心概念

开放环测试按时间表提交请求。客户端在途数占满时，新请求在发出 HTTP 之前等待。比较前后半程的等待和积压，可以发现整轮 P90 掩盖的队列增长。末次提交后的未完成量同时包含正在处理和仍在等待的请求。

## 示例与练习

沿用 Ollama、本机 Qwen3 8B、两个推理槽与两条在途上限。每轮提交 32 条请求，交替使用 190 和 889 token 的输入，输出目标为 117 token。两档分别按 800 ms 和约 667 ms 的间隔提交，第二轮反转顺序。每半程用 16 条请求计算排队统计。[复现入口](../../../practice/local-inference/README.md#固定到达速率测试)

| 到达速率 | 轮次 | 排队 P90 前半程 | 排队 P90 后半程 | 已等待的最大条数，前半程 → 后半程 | 最后一次提交后未完成 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1.25 条/s | 1 | 5.71 ms | 7.04 ms | 0 → 0 | 2 |
| 1.25 条/s | 2 | 5.63 ms | 5.29 ms | 0 → 0 | 2 |
| 1.50 条/s | 1 | 632.50 ms | 1875.79 ms | 0 → 2 | 5 |
| 1.50 条/s | 2 | 891.75 ms | 2115.89 ms | 1 → 2 | 5 |

128 条请求全部返回 HTTP 200、完整目标正文和正常终止标记。实际提交速率与目标一致至小数点后两位，最大提交偏差为 0.56 ms。提示缓存计数为 0–5 token。两轮合并，1.25 和 1.50 条/s 的提交至完整回复 P90 分别为 1.49 和 3.34 秒。[逐次记录](../../../practice/local-inference/results/2026-11-24-capacity.json)

### 等待增加在哪一段

把每条请求拆成提交后等待客户端放行、开始 HTTP 后读完回复两个阶段。下表合并相同速率的两轮，每个半程有 32 条请求，统计各段均值。端到端 P90 从逐条总耗时计算。

| 到达速率 | 半程 | 放行前平均等待 | 开始 HTTP 至回复结束平均耗时 |
| ---: | --- | ---: | ---: |
| 1.25 条/s | 前 | 5.32 ms | 1436.77 ms |
| 1.25 条/s | 后 | 5.34 ms | 1436.99 ms |
| 1.50 条/s | 前 | 387.33 ms | 1450.60 ms |
| 1.50 条/s | 后 | 1490.93 ms | 1463.98 ms |

每秒 1.50 条时，后半程的放行前平均等待增加约 1104 ms，HTTP 阶段只增加约 13 ms。只从 HTTP 开始计时会漏掉这轮长负载的大部分延迟增长。周三的过载对照将从提交时刻开始计等待预算。

### 中间速率 1.375 条/s

保持相同模型、两个槽、两条在途上限以及输入和输出，补跑两轮 48 条请求，提交窗口约 34 秒。96 条全部通过，按实际提交时刻算出的到达速率为 1.375 条/s。[中间速率逐次记录](../../../practice/local-inference/results/2026-11-24-capacity-midpoint.json)

| 轮次 | 排队 P90 前半程 | 排队 P90 后半程 | 最后一次提交后未完成 | 停止提交至全部完成 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 345.21 ms | 690.00 ms | 3 | 2.11 秒 |
| 2 | 213.84 ms | 501.75 ms | 3 | 1.90 秒 |

两轮里，到达时已经在等候的最大条数都为 0。这个指标不计刚到的新请求，所以它为 0 时，新请求仍可能要等在途请求完成。实际排队时间和末次提交后未完成量进一步表明，每秒 1.375 条时等待已经开始累积。

## 遇到的问题

1.50 条/s 的回复全部通过，但两轮后半程都比前半程多出约 1.2 秒的排队 P90。把停止提交后的排空计入吞吐，1.375 和 1.50 条/s 两档的整轮完成速率均为约 1.32–1.33 条/s。三档提交窗口约为 21–34 秒，结果适用于当前输入混合和在途限制，长期容量还需在更长窗口验证。

## 今日总结

今天共验收 224 条请求。1.25 条/s 维持了毫秒级等待，1.375 条/s 已出现等待增长，1.50 条/s 的积压更明显。当前负载下，低等待到明显增长的过渡范围缩小到 1.25 至 1.375 条/s。周三的过载对照沿用两条在途上限和逐次计时。
