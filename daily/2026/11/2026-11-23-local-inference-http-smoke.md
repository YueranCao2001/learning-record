# 2026-11-23：本地推理实作：跑通第一条 HTTP 回复

## 今日目标

本地大模型推理服务与压测。先验收普通和流式 HTTP 回复，再建立短、长提示的单并发基线，并回答并发从 1 提到 2 后，吞吐和单条延迟如何变化。并发对照固定请求数、提示长度和验收规则，记录实际在途数、缓存命中、延迟、吞吐及失败，最后从新服务实例复跑检查结果方向。[练习入口](../../../practice/local-inference/README.md)

## 核心概念

- `/api/version` 成功说明 HTTP 服务已启动。第一次 `/api/chat` 还要加载模型并完成生成，才能验证整条推理链路。
- `stream: false` 一次性返回完整 JSON。`stream: true` 逐行返回 NDJSON，客户端拼接每个 `message.content`，收到 `done: true` 后验收整段回复。计时从客户端发送请求开始，首段正文取第一条含非空白正文的事件。一个事件可以包含多个 token，因此这里测的是客户端可见的首段时间。[Ollama 流式响应文档](https://docs.ollama.com/api/streaming)

### 同一实例上的并发 1 与 2

五档从观察到入槽日志到开始断开的中位数都在 0.066–0.076 ms，断开前均未探测到可读响应。25 次后续回复全部通过。逐次计算取消日志和释放日志的间隔，各档中位数为 9.37–11.58 ms。两端和三档部分命中都显示，未复用的 token 越多，断开到取消日志之间的时间越长。

## 遇到的问题

原计划使用独立 llama.cpp Windows 包和 Qwen3-0.6B GGUF。官方运行包未能及时下载，Hugging Face GGUF 下载连接超时。检查时发现 Ollama 已安装且有 `qwen3:8b` 缓存，因此首日用这套组合完成同一个本机 HTTP 验证。后续性能对照需要固定服务实现、模型和运行配置。

流式对照的预热请求耗时 3.99 秒，服务端报告加载耗时 3.67 秒。后续重复提示都复用了 47 个 token 中的 46 个。单并发基线改用新开头和原样重发来分组，首发仍有 3 个公共模板 token 命中。重发固定发生在首发之后，因此结果适用于紧邻重复请求的场景。

并发阶段固定服务端的两个槽，只改变客户端在途请求上限。前一阶段基线的服务端只有一个槽，并发对照使用本阶段的并发 1 数据作为对照。每次运行每种并发只有 16 条正式请求，四次均在同一台机器上完成，结果适用于当前的短输出混合负载。

为让输出长度对照使用一样长的输入，两个目标文本都加入每条提示。输入因此比前一轮的 51 和 750 token 更长。本次用同一张表里的短输出组衡量相对差异。

首段正文延迟从客户端实际发送 HTTP 请求开始，包含网络往返、服务处理和可能的服务端等待。实验确认服务只有两个槽，并测到了四个在途请求下的延迟变化。服务日志未给出逐条的排队起止时间，因此这里只量化客户端端到端等待。

若服务统计只从收到 HTTP 请求开始，客户端放行前的等待会落在这套计时之外。比较调用方体验时，两组都从整批提交时刻计时，再用发送前与发送后的指标定位耗时。

真实 Ollama 请求在 40 ms 组的 HTTP 超时均发生于客户端收到状态码之前。另用合成回环服务先返回 HTTP 200 再延迟正文，验证收到状态码仍会触发首段超时。客户端报告退出时间比预算晚约 3–22 ms，截止时间用来判定正文是否达标，线程和套接字的退出时间单独记录。

槽释放实验的客户端事件与 runner 日志使用同一单调时钟。服务侧时点取日志行到达采集程序的时间，包含输出和调度开销。首段前取消使用不同的断开时点和候选输入长度，单独报告其时间数据。

双槽对照覆盖两个槽都已输出首段后的取消。保留流的完成结果有逐次证据，约 45 ms 的中位耗时差来自同一台设备上的 6 对请求，当前仅作记录。

排队断开组的观测持续到同批后续回复读完，这段日志只记录了占槽请求和后续请求。已占槽组当前量到的是取消和释放日志到达的时点，runner 内部各处理阶段的耗时仍待分段测量。

提示长度对照使用低缓存前缀和接近一致的客户端断开时点。四档数据可以比较日志之间的时间分布，确定 runner 在哪一段提示计算中处理取消还需要更细的服务端事件。

缓存对照每对固定按新开头、完整预热、原样重发的顺序执行。结果覆盖这台设备与当前 Ollama runner 的这两种缓存条件，逐次记录保留了实际缓存计数和后续任务的同槽复用。

部分命中对照中的未复用 token 用总提示 token 数减去 runner 首次报告的缓存位置。这个量便于比较各组，runner 内部阶段的耗时仍需独立观测。

等量未缓存对照的长短差按同一轮的两次请求先相减，再取 8 个差值的中位数。全部配对来自同一服务实例，入槽日志到断开的时间也逐条保留，复跑可进一步检验这几毫秒的差异是否稳定。
