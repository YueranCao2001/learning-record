# 2026年10月12日 用诊断案例区分检索表示与排序

## 今日目标

继续 [昨天的共享检索基线](2026-10-11-reusable-retrieval-baseline.md)，今天补充能区分现有配置的案例，解释为什么三个方法在原问题集上得到相同覆盖率。

本次只扩展合成数据和运行入口，不改变检索算法、词典或 BM25 参数。目标是观察词频、长度与词边界如何改变逐题排名，而不是报告某种方法在真实业务中更好。原文引用检查留作下一项未完成产物。

## 核心概念

覆盖率与排名敏感性不同。如果两个候选都进入 Top-2，首位顺序发生变化也可能不影响完整覆盖。本次同时运行 Top-1 与 Top-2，避免只看相同的总分。

构造案例适合诊断已知机制，不适合作为独立质量验证。新增 required 标注表示预先指定的诊断目标，不能解释为唯一的语义证据。例如长短片段都包含保修期限，短片段是长度诊断的目标，不意味着长片段不能支持正确回答。

每组新增案例采用独立读者范围。因为共享实现从可见片段计算 N、df 和平均长度，隔离读者也隔离了这些统计量；原问题的可见语料保持不变。这是教学实验的控制方式，不代表真实多租户系统必须采用同一种统计方案。

## 示例与练习

### 数据与运行前预期

[baseline-v2.json](../../../practice/rag-baseline/data/baseline-v2.json) 保留四个原片段与五道原问题，再增加九个片段和三道诊断问题。每组包含两个候选和一个无关片段，数据中的 design 保存运行前的预期方向。

| 案例 | 构造方式 | 预期观察 |
| --- | --- | --- |
| 词频 frequency | 两段都匹配退货，一段重复退货三次 | 交集计数并列；BM25 的词频与长度处理可能改变首位 |
| 长度 length | 同一保修事实，一段附加大量说明文字 | 交集计数并列；BM25 可能将短片段排在前面 |
| 词边界 boundary | 查询设备支持，对比普通设备支持与设备不支持 | 最长匹配词典与字符二元组的匹配词项不同，可能改变首位 |

交集并列时，原实现按 ID 排序，所以 a 开头的候选排在 z 开头之前。这个命名用来让并列行为可见，不是语义判断。

词频案例增加重复词也增加了长度，不能把它描述成完全隔离长度的词频消融。这里观察的是固定 BM25 参数下两种作用共同产生的排序结果。

### 重跑命令与产物

从仓库根目录执行，仍只使用 Python 标准库：

```powershell
python -m unittest discover -s practice/rag-baseline -p "test_*.py" -v
python -X utf8 practice/rag-baseline/run.py --dataset practice/rag-baseline/data/baseline-v2.json --k 1
python -X utf8 practice/rag-baseline/run.py --dataset practice/rag-baseline/data/baseline-v2.json --k 2
```

本次用 Python 3.12.14 实际运行。输出分别保存为 [Top-1 报告](../../../practice/rag-baseline/results/2026-10-12-v2-top1.json) 和 [Top-2 报告](../../../practice/rag-baseline/results/2026-10-12-v2-top2.json)。每份含八道题乘三种配置的 24 条记录，保留数据、代码指纹和逐题分数。

### 实际结果

12 项测试全部通过，包括旧结果回归、原问题在 v2 中保持一致、新案例预期方向、输入重排和读者隔离。三个新增案例的首位如下：

| 配置 | 词频 | 长度 | 词边界 |
| --- | --- | --- | --- |
| word overlap | a_freq | a_long | a_boundary |
| word BM25 | z_freq | z_short | a_boundary |
| bigram BM25 | z_freq | z_short | z_boundary |

词频和长度案例区分了交集排序与 BM25；词边界案例区分了两种表示。Top-2 下，三个配置都包含每个新增案例的目标片段，完整覆盖率再次相同。

原五道题的逐题结果和分数，在相同 k 下与 v1 一致。近义表达质保多久仍没有候选，新增诊断没有修复它，也没有改变原无答案题的空结果。

报告中的 v2 总分混合原证据标注与新增诊断目标，仅用于检查这份构造数据。不能将它与 v1 的 3/4 比较并宣称准确率改善，也不能把二元组的首位变化当作否定语义理解。

## 遇到的问题

原问题集只显示三个方法都能将同样的证据放入 Top-2，并未覆盖会暴露词频、长度或词边界差异的输入。需要修正的判断是：总分相同不代表检索行为相同，更不代表增加一种方法没有意义。

新增案例有意放大机制差异，也沿用了人工指定的诊断目标。这种设计偏向已知行为，因此适合解释实现，不足以用于选择生产检索器。后续还需要独立问题和语义证据标注。

词边界案例中，设备不支持在词典表示下可能排名更高。候选与问题包含相同词，并不意味着它支持肯定答案；二元组选中了另一段，也不代表它理解了否定逻辑。

## 今日总结

今天完成了有版本的诊断数据、Top-1 与 Top-2 报告以及四项新增测试。检索实现未改变，变化来自输入设计和观察窗口。

新增结果解释了原总分无法区分方法的原因，没有证明真实检索质量提升。v1 数据和历史报告保持不变，已知近义漏召回继续保留。
