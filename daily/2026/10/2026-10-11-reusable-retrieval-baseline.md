# 2026年10月11日 将文本检索练习整理为共享基线

## 今日目标

当前处于 [最小 RAG 项目](../../../topics/rag.md) 的共享检索基线阶段。今天不增加算法，而是落实 [昨天的下一步计划](2026-10-10-chinese-tokenization-bm25-experiment.md#下次衔接建议)：将原文、权限、问题、检索与评估从笔记代码块整理成可以独立重跑的项目。

今天解决的问题是如何保留同一个实验起点，让后续改动能与已有结果逐题比较。新增产物为共享代码、固定 JSON 数据、测试和实际结果快照；检索质量没有提升，也没有运行生成模型。

## 核心概念

共享基线不是重写一个更复杂的例子，而是保持输入、分析器、排序和评估含义不变，再把它们拆成可复用工件。

检索层只接收文档、查询、读者和配置，不读取 required 证据标注。评估层计算证据召回与完整覆盖，无答案题的这两个指标为 null，并另外记录是否返回候选。这样既避免将空标注算作满分，也保留了检索与评估的边界。

结果报告保存逐题排名与分数，不能只保留 3/4 的汇总值。数据与代码指纹关联本次运行的输入和实现；指纹相同不等于模型或系统能力已经通过验收。

## 示例与练习

### 固定输入与共享代码

项目位于 [practice/rag-baseline](../../../practice/rag-baseline/README.md)，只依赖 Python 标准库。

| 产物 | 本次用途 |
| --- | --- |
| [retrieval.py](../../../practice/rag-baseline/retrieval.py) | 从昨天代码提取分析器与检索，新增逐题分数输出，保留原排序规则 |
| [baseline-v1.json](../../../practice/rag-baseline/data/baseline-v1.json) | 固定四个合成片段、权限与五道问题，版本为 synthetic-policy-v1 |
| [run.py](../../../practice/rag-baseline/run.py) | 运行三种配置，输出逐题 JSON 及数据、代码指纹 |
| [test_baseline.py](../../../practice/rag-baseline/test_baseline.py) | 检查旧结果、权限、顺序、gold 隔离及非法输入 |
| [本次结果快照](../../../practice/rag-baseline/results/2026-10-11-baseline.json) | 保存实际运行的三种配置与 15 条逐题记录 |

保留 word overlap、word BM25 与 bigram BM25。查询按不同词项集合计分，BM25 仍使用可见片段统计、log(N/df)、k1=1.2 与 b=0.75。今天没有修改词典或加入同义词，以免将代码整理与质量改进混在一起。

### 运行方式

从仓库根目录执行：

```powershell
python -m unittest discover -s practice/rag-baseline -p "test_*.py" -v
python -X utf8 practice/rag-baseline/run.py
```

本次使用本机 Python 3.12.14 执行上述入口。运行器向标准输出打印 JSON，结果快照保存该实际输出；它不会自动覆盖已有快照。

### 实际结果

8 项 unittest 测试全部通过。另将共享检索与昨天的原始代码逐题比较，15 条排名全部一致；保存的 JSON 与重跑报告完全一致，从其他工作目录启动也得到相同报告。三个配置的汇总如下：

| 配置 | 有答案题数 | 完整覆盖题数 | 完整证据覆盖率 |
| --- | --- | --- | --- |
| word overlap | 4 | 3 | 3/4 |
| word BM25 | 4 | 3 | 3/4 |
| bigram BM25 | 4 | 3 | 3/4 |

三个配置均返回定制问题的 exception、rule 两条证据；近义题 synonym 与无答案题 missing 均没有候选。近义题的证据召回为 0，无答案题的证据召回为 null，两者不能混为同一种成功或失败。

测试还检查改变 gold 标注不会改变检索排名、重排文档不会改变结果、未知读者无结果、不可见 gold 被拒绝、重复 ID 与非法 k 被拒绝。否定查询与原查询排序相同的案例继续保留，说明检索没有解释肯定与否定的语义。

## 遇到的问题

原来只有笔记代码块和汇总输出，后续很容易重复实现相似函数，也不便对照逐题变化。现在共享代码与固定输入成为后续实验起点，日期笔记只记录当天的变化和结果。

需要修正的推进方式是先有可重跑基线，再扩展同义词。昨天的三种配置覆盖率相同，既不能证明 BM25 优于交集排序，也不能说明二元组在真实任务上没有价值；当前案例缺乏区分能力。

本次仍然使用合成政策。原文引用检查尚未迁移到共享模块，新增词频、长度与词边界案例也尚未完成；现有测试不能代表完整 RAG 的正确性或安全性。

## 今日总结

今天完成了从笔记代码到共享检索项目的整理，保留了原结果，并保存可逐题核对的实际输出。新增的是可复用与可追溯的实验工件，不是检索质量改善。

近义漏召回和配置间无差异都属于后续需要解释的结果，不应通过替换测试题或提前增加规则将它们隐藏。

## 下一步

1. 在独立版本的固定数据中补充词频、长短片段与词边界案例，事先写明希望观察的差异，再运行现有三种配置；保留 v1 的原结果。
2. 检查逐题排名、证据覆盖与新增误召回；如仍无差异，记录原因与下一项可检验假设，不宣称改进。
3. 将已有原文引用检查接入共享项目，覆盖来源版本、引用文本和输入证据集合，明确它仍不判断语义支持。

下一项产物是扩展后的固定数据、逐题对照报告与引用检查测试。同义词扩展和生成模型仍在后续阶段，不作为当前基线已经完成的能力。
