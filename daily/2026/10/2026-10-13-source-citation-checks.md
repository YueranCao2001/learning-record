# 2026年10月13日 将原文引用检查接入共享检索项目

## 今日目标

接着 [昨天的诊断案例](2026-10-12-retrieval-ranking-diagnostic-cases.md)，今天落实原文引用检查，将固定来源快照、检索后的证据包和引用核验接到同一个共享项目。

今天解决的问题是引用是否来自实际输入证据、是否仍有权限、是否与绑定版本的原文一致。不新增检索算法，不运行生成模型，也不把原文检查当作答案正确性判断。

## 核心概念

引用至少有三条独立约束：来源在当前读者的允许范围内；片段确实被组装进输入证据包；版本、位置和引文与固定原文相符。来源存在或曾被检索到，都不足以代替后两项检查。

沿用 [9 月 27 日的原文核验思路](../09/2026-09-27-rag-retrieval-evidence-citations.md)，这次将检查整理为共享模块，并加入当前权限和引用声明的来源版本核对。来源、版本和权限由应用层传入，不由回答中的引用自行决定。

偏移使用 Python 字符串索引，范围为左闭右开的 start、end，不是 UTF-8 字节位置或模型 token 位置。核验使用未经检索规范化的原文；不能先删标点或做字符转换，再声称引文逐字一致。

片段 ID 根据来源、版本、范围和文本生成摘要，用来绑定记录，不是来源真实性的签名。快照的可信建立和生产系统权限同步仍属于外层职责。

### 实际结果

21 项测试全部通过，其中 12 项为既有检索测试，9 项为新增引用测试。演示的十个案例全部符合预设检查结果：

| 案例 | 原文检查结果 | 含义 |
| --- | --- | --- |
| 正常引用 | 通过 | 引文来自当前输入并逐字匹配 |
| 伪造片段 ID | 拒绝 | ID 不属于本次证据包 |
| 篡改引文 | 拒绝 | 文本与来源子区间不符 |
| 错误版本 | 拒绝 | 引用声明与绑定版本不符 |
| 错误来源 | 拒绝 | 引用声明与绑定来源不符 |
| 未进入上下文的片段 | 拒绝 | 可读取不代表本次已输入 |
| 越界引用 | 拒绝 | 引文范围超出输入片段 |
| 变更来源快照 | 拒绝 | 旧片段不能匹配被修改的来源 |
| 当前撤权 | 拒绝 | 旧证据包不能代替当前允许集合 |
| 真实引文搭配错误结论 | 通过 | 原文一致不等于语义支持 |

最后一例引用普通设备支持30天内退货，却提出所有设备都支持该退货规则。结论扩大了范围，也忽略了同时输入的定制设备例外。检查函数没有接收或评估结论，因此不会检测这个语义错误；报告明确将 semantic_support 标为 not_evaluated。

新增单元测试还覆盖中文子区间、空区间、负偏移、布尔偏移、缺失快照、重复证据 ID、篡改片段、子片段边界、重复来源版本，以及组装时版本或原文不匹配。

## 遇到的问题

旧笔记已经讨论来源核验，但共享检索项目此前只输出 ID 和分数，缺少绑定版本与原文的输入证据。现在补齐了这段接口，引用检查不再凭全语料中存在某个来源就接受引用。

需要保持的区分是原文一致性、语义支持与答案正确性。十个案例都符合预期，只证明这组规则与反例按设定工作，不是问答准确率、安全通过率或生产系统验收结果。

当前证据包直接使用 Top-2，没有预算裁剪或生成调用。允许集合是本地模拟的当前权限输入，未实现跨服务权限更新、并发撤权或真实来源认证。所有文本仍为合成政策。

## 今日总结

今天完成了固定来源快照、从检索到证据组装的接口，以及共享原文引用检查和实际案例报告。旧检索逻辑未改变，新增的是输入证据的可追溯核验。

真实引文搭配错误结论的反例仍然通过，这是检查范围的明确边界。后续必须单独评价答案是否被证据支持，不能通过增加更多字符串断言冒充语义判断。

## 下一步

同时准备小型、独立审查的问题与语义支持标注，保留规则加例外、无答案、版本冲突和相关但不支持的案例。明确模型或 API、预算和数据范围后再接入实际生成，报告答案正确、引用支持、拒答及成本，不用合成引用通过数替代这些指标。
