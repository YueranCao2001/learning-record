# 2026年10月27日 中文信息抽取微调：字段遗漏的提示对照与阶段验收

## 今日目标

在 [昨天的精确续训实验](2026-10-26-sft-exact-training-resume.md) 后，整理工程验证边界，并回到尚未解决的明确地点遗漏。今天扩大到20条固定通知、三种提示、两个固定模型，共120次真实GPU生成，0步训练。

要检查的具体问题是：候选在时间缺失时遗漏地点，能否通过改变提示缓解？缓解原题时是否在其他题目产生退化？结果显示，补充逐字段判断规则在本次候选诊断中从17/20达到20/20，但同一规则让基座出现格式退化；仅调整字段顺序也引入了时间遗漏。提示效果依赖模型和样例，不能直接推广。

## 核心概念

- JSON键顺序不改变当前评分语义，但提示中的顺序会改变输入token，模型实际生成的字段顺序也可能改变。应记录原始输出，不能把语义等价误当作模型行为一定相同。
- “修好原题”与“通过回归检查”不同。旧审计题和新增配对题分开统计，保留修复、退化和格式失败的逐题记录。
- 同源的时间有无配对共享活动、地点和表达方式，不能当作两条独立来源。4个来源组也不是4个独立模板族；本次仍是已见失败引导的开放合成诊断。
- 推理沿用原非思考chat template和生成入口。消息经 `apply_chat_template` 转为token；`max_new_tokens=128`限制新增token，`do_sample=False`固定为贪心路径。[Transformers 4.57.1 模板说明](https://huggingface.co/docs/transformers/v4.57.1/en/chat_templating)、[生成参数](https://huggingface.co/docs/transformers/v4.57.1/en/main_classes/text_generation)

### 2. 三种提示分别只改一处

原提示保持10月22日以来的版本：

```text
提取活动名称、时间和地点。只输出 JSON 对象，键为 event、time、location。值必须逐字来自输入；未提供的字段用 null。不要推断日期或补全地点。
```

| 条件 | 相对原提示的变化 |
| --- | --- |
| original | 不变 |
| key-order | 只将“键为 event、time、location”替换为“键为 event、location、time” |
| field-independence | 只在末尾追加“分别判断三个字段是否在原文中明确给出；一个字段缺失不影响提取其他字段。” |

调序条件不同时追加规则；规则条件不调序。预算、标签、生成顺序和评分在运行前固定，生成后未为追求分数修改提示或重试选优。提示长度和内容会随干预变化，因此不将效果归因于某个内部注意力机制。

### 4. 新配对将地点遗漏扩展到两个来源

以pair-01为例：

```text
面向初学者的活动已确定：活动名称为纸雕体验课。场地设在流萤教室，开课时间另行公布。
```

预期为 `event="纸雕体验课"`、`time=null`、`location="流萤教室"`。配对版本只把最后时间分句改成“开课时间为11月21日14:00”，相应time标签改成原文时间片段。

| 新来源 | 原候选时间缺失时地点 | 原候选时间明确时地点 | 两种干预下的地点 |
| --- | --- | --- | --- |
| 纸雕体验课 / 流萤教室 | 错误null | 流萤教室 | 均正确 |
| 植物拓印课 / 溪石工坊 | 错误null | 溪石工坊 | 均正确 |
| 陶片拼贴课 / 白鹭展室 | 白鹭展室 | 白鹭展室 | 均正确 |
| 风筝制作课 / 晴川活动室 | 晴川活动室 | 晴川活动室 | 均正确 |

基座在新8题中的地点全部正确，其主要错误是时间片段不完整。候选的遗漏从原audit-03扩展到两个新来源，并未在所有时间缺失样例发生。原题和新来源都支持提示敏感性的诊断，尚不足以解释训练中哪一条数据或哪一步更新造成该行为。

### 5. 修复和退化同时记录

候选调序后，audit-03与pair-01/02的缺时间版本三个地点遗漏都被修复，但原本正确的audit-04发生新退化：

```text
这次活动是科学摄影讲座，11月14日上午09:30开始。场地还在安排中。
```

调序后的候选输出：

```json
{"event":"科学摄影讲座","location":null,"time":null}
```

地点缺失正确，明确时间却被丢掉。旧审计总数仍为11/12，掩盖了“修好一题、弄坏另一题”。候选追加规则条件修复三题，当前20题中未出现新的整条退化。

基座的行为不同。追加规则后audit-05、audit-11从原本正确退化，另有audit-12继续错误；这三题都输出Markdown围栏，契约仅通过17/20。audit-11的围栏内还把活动名写成“活动公告”，不是单纯清理围栏就能修复。不能将候选上的规则效果自动套给基座。

## 遇到的问题

旧12题合计11/12并不能证明“没有退化”，必须按ID比较修复与新错；地点指标也不能替代时间和格式回归。此前单来源的表面变化诊断，今天补成四个新来源组的配对，但仍缺少独立模板族和人工标注复核。

所有20题都已经开放，规则提示又是针对已知问题提出的。20/20只支持“这组固定候选和诊断输入上有效”，不能作为泛化准确率或已完成通用修复。今天没有改变权重，不是新一轮微调质量提升。
