## 1. 从二维旋转开始

二维向量 `[x₁, x₂]` 旋转角度 `θ` 后为：

```text
[x₁']   [cos θ  -sin θ] [x₁]
[x₂'] = [sin θ   cos θ] [x₂]
```

也就是：

```text
x₁' = x₁ cos θ - x₂ sin θ
x₂' = x₁ sin θ + x₂ cos θ
```

例如 `[1, 0]` 旋转 90° 后变成 `[0, 1]`。旋转不会改变向量长度，因为旋转矩阵是正交矩阵：

```text
R(θ)ᵀR(θ) = I
```

RoPE 的基本做法，就是把 Q 和 K 的特征维度两两分组，并对每一对二维特征进行位置相关的旋转。

## 2. 位置如何变成旋转角度

设 token 位于位置 `m`，第 `i` 对二维特征使用频率 `ωᵢ`，旋转角度为：

```text
θ(m, i) = m · ωᵢ
ωᵢ = base^(-2i / d)
```

常见 `base` 为 10000，`d` 是应用 RoPE 的特征维度。不同特征对采用不同频率：高频更敏感于近距离变化，低频能在更长范围内缓慢变化。

对一个头的向量：

```text
[x₀, x₁, x₂, x₃, ...]
```

可以配成：

```text
(x₀, x₁), (x₂, x₃), ...
```

每对维度使用自己的频率旋转，因此 RoPE 通常要求被旋转的维度为偶数。

## 3. 为什么点积携带相对位置

令位置 `m` 的 Query 为 `R_m q`，位置 `n` 的 Key 为 `R_n k`。两者点积：

```text
(R_m q)ᵀ(R_n k)
= qᵀR_mᵀR_n k
= qᵀR_(n-m) k
```

第二步利用了旋转矩阵的性质：

```text
R_mᵀ = R_(-m)
R_(-m)R_n = R_(n-m)
```

最终结果中的位置只通过 `n - m` 出现。因此，虽然 Q 和 K 分别使用各自的绝对位置旋转，它们的注意力点积却自然包含相对位置差。

一个直接推论是：如果同时把两个位置平移相同距离 `c`，相对距离不变，点积也不变：

```text
(n + c) - (m + c) = n - m
```

## 4. 最小 NumPy 实现

下面约定输入最后一维按相邻元素配对：

```python
import numpy as np


def rope_angles(
    sequence_length: int,
    head_dim: int,
    base: float = 10000.0,
) -> tuple[np.ndarray, np.ndarray]:
    if head_dim % 2 != 0:
        raise ValueError("head_dim 必须是偶数")

    positions = np.arange(sequence_length, dtype=np.float64)[:, None]
    pair_indices = np.arange(0, head_dim, 2, dtype=np.float64)
    frequencies = 1.0 / np.power(base, pair_indices / head_dim)
    angles = positions * frequencies[None, :]
    return np.cos(angles), np.sin(angles)


def apply_rope(x: np.ndarray) -> np.ndarray:
    """对形状 [..., sequence_length, head_dim] 的数组应用 RoPE。"""
    sequence_length, head_dim = x.shape[-2:]
    cos, sin = rope_angles(sequence_length, head_dim)

    # 为 batch/head 等前导维增加广播维度。
    broadcast_shape = (1,) * (x.ndim - 2) + cos.shape
    cos = cos.reshape(broadcast_shape)
    sin = sin.reshape(broadcast_shape)

    x_even = x[..., 0::2]
    x_odd = x[..., 1::2]

    output = np.empty_like(x, dtype=np.result_type(x, np.float64))
    output[..., 0::2] = x_even * cos - x_odd * sin
    output[..., 1::2] = x_even * sin + x_odd * cos
    return output
```

如果 Q、K 的形状是 `[batch, heads, sequence_length, head_dim]`，上述实现会在 batch 和 head 维上共享相同的位置旋转参数。

## 5. 验证形状和向量长度

```python
rng = np.random.default_rng(42)
q = rng.normal(size=(2, 4, 6, 8))
k = rng.normal(size=(2, 4, 6, 8))

q_rot = apply_rope(q)
k_rot = apply_rope(k)

assert q_rot.shape == q.shape
assert k_rot.shape == k.shape
np.testing.assert_allclose(
    np.linalg.norm(q_rot, axis=-1),
    np.linalg.norm(q, axis=-1),
)
```

旋转改变方向但不改变长度，因此每个 token、每个头的向量范数应保持不变。

## 6. 验证相对位置性质

为了清晰验证，可以直接编写二维旋转函数：

```python
def rotate_2d(x: np.ndarray, angle: float) -> np.ndarray:
    cos = np.cos(angle)
    sin = np.sin(angle)
    return np.array([
        x[0] * cos - x[1] * sin,
        x[0] * sin + x[1] * cos,
    ])


q = np.array([1.2, -0.7])
k = np.array([0.3, 2.0])
frequency = 0.4

m, n = 2, 5
shift = 7

score_1 = rotate_2d(q, m * frequency) @ rotate_2d(k, n * frequency)
score_2 = (
    rotate_2d(q, (m + shift) * frequency)
    @ rotate_2d(k, (n + shift) * frequency)
)

np.testing.assert_allclose(score_1, score_2)
```

两组位置分别是 `(2, 5)` 和 `(9, 12)`，绝对位置不同，但相对距离都为 3，因此点积相同。

## 7. RoPE 在 Attention 中的位置

简化流程如下：

```text
X → 线性投影 → Q, K, V
Q, K → 拆分多头
Q, K → 应用 RoPE
QKᵀ / √d_head → Mask → Softmax → 与 V 加权
```

重要结论：

- RoPE 通常作用于拆分多头后的 Q、K。
- V 不参与 QK 点积，因此通常不旋转 V。
- RoPE 一般在计算注意力分数之前应用。
- 旋转不会改变 Q、K 的形状，所以后续 Attention 公式不变。

## 8. 部分旋转维度

一些实现只旋转每个头的前 `rotary_dim` 个维度，其余维度保持不变：

```text
head_dim = rotary_part + untouched_part
```

此时要求 `rotary_dim` 为偶数，但不一定等于完整 `head_dim`。这样可以让一部分特征显式携带旋转位置信息，另一部分保持普通内容表示。

阅读模型代码时应确认：

- `rotary_dim` 是多少。
- 特征如何配对：相邻配对还是前后半区配对。
- 位置从 0 开始还是包含缓存偏移。
- cos/sin 缓存的形状如何广播。

## 9. KV Cache 中的位置偏移

自回归生成时，过去 token 的 K、V 会缓存在 KV Cache 中。生成新 token 时，它的位置不能重新从 0 开始，而应使用：

```text
position = 已缓存 token 数量 + 当前局部索引
```

否则新 Query 的旋转角度会与缓存 Key 的绝对位置不一致，相对位置关系也会错误。工程实现通常通过 `position_ids`、`cache_position` 或偏移量传入正确位置。

## 10. 长度外推的边界

RoPE 可以为更大位置计算旋转角度，但这仍不保证模型在超出训练长度后表现稳定。原因包括：

- 训练时没有见过对应的相对距离分布。
- 高频维度在远距离下快速旋转，模式可能发生混叠。
- 注意力、数据分布和其他模块也受到上下文长度影响。

实际长上下文模型可能采用频率缩放或其他 RoPE 扩展策略。理解这些方法之前，应先掌握标准 RoPE 的频率、角度和相对点积性质。

## 11. 常见错误

- 对 V 旋转，却忘记真正决定注意力分数的是 Q 和 K。
- `head_dim` 为奇数仍强行两两配对。
- 把位置编码加到 Q/K 上，误当成 RoPE 的旋转操作。
- cos 和 sin 广播维度错误，意外跨序列或头混合数据。
- Q 与 K 使用不同的位置编号或不同的频率表。
- KV Cache 生成时忘记位置偏移，导致新 token 从位置 0 旋转。
- 认为能计算任意位置角度就等于拥有可靠的无限上下文。

## 今日总结

一句话总结：**RoPE 用位置控制 Q、K 的二维旋转，使注意力点积自然依赖相对位置差。**

最核心的公式是 `(R_m q)ᵀ(R_n k) = qᵀR_(n-m)k`。实现时则要持续检查配对方式、偶数维约束、cos/sin 广播以及 KV Cache 的位置偏移。
